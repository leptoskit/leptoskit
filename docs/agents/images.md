# Images: host them, don't commit them

Raster images (screenshots, photos, icons) do not get committed to this repository. They grow the clone for everyone, forever, and git is the wrong tool for serving them. Host the image instead and link the URL from the Markdown. `devenv shell lint:images` (run as part of `lint:all` and CI) fails when a tracked file has an image or video extension that is not in [`.github/allowed-images.txt`](../../.github/allowed-images.txt), or when an allowlisted file outgrows 16 KiB without the scaffolding exemption. The rule and the check live in [`setup/scripts/check_images.sh`](../../setup/scripts/check_images.sh).

## Backblaze B2

The repository's public bucket is `leptoskit`, served from `https://f002.backblazeb2.com/file/leptoskit/<path>`. The examples live under `examples/`, the docs images under `docs/`.

Upload with the B2 CLI (already authorised on the maintainer machines through `~/.config/b2/account_info`):

```sh
nix run nixpkgs#backblaze-b2 -- upload-file --no-progress leptoskit \
	docs/src/assets/screenshot.png docs/screenshot.png
```

Then check the URL serves the same bytes you uploaded: the status must be 200 and the sha256 must match the local file.

```sh
url=https://f002.backblazeb2.com/file/leptoskit/docs/screenshot.png
curl -s -o /tmp/download -w "%{http_code}\n" "$url"
shasum -a 256 /tmp/download docs/src/assets/screenshot.png
```

Link the absolute URL from Markdown, a `<Shot src="…">`, or wherever the image appears, and do not commit the local file. Uploads are public and permanent: upload only what belongs in the repository, never anything personal.

## GitHub attachments

For one-off images in an issue or pull request — a screenshot proving a fix, a picture in a bug report — attach it to a comment and link the URL GitHub returns:

```sh
gh pr comment --attach screenshot.png --body "After the fix:"
```

The returned `https://github.com/user-attachments/…` URL is permanent; use it in the Markdown. (House rule: `gh pr create`, `gh pr edit`, `gh issue
create`, `gh issue edit`, and `gh issue comment` all take `--attach`.)

## The allowlist

[`.github/allowed-images.txt`](../../.github/allowed-images.txt) records the tracked images that stay in the repository, one git path per line, with the reason in a comment above each group. A line starting with `!` also exempts the file from the 16 KiB limit — that is for platform toolchain scaffolding whose bytes the toolchain requires, such as the Flutter and React Native benchmark apps' template icons, which ship with committed scaffolds and are not regenerated by any build step. The four kinds of entries:

- Brand vectors: hand-authored SVGs the docs site links and shows.
- Fixtures: a test's input bytes (site generator fixtures, UIKit probe images).
- Toolchain templates and example assets: SVGs the CLI writes into generated apps, or an example's build reads from `leptoskit.toml`.
- Benchmark scaffolding: Flutter and React Native platform templates, built in place.

When a test genuinely needs image bytes as its input, add the fixture here with a reason. When an image is content someone looks at, host it.

## History

Existing commits keep their images; this rule only stops further growth. Do not rewrite history to shrink the repository.

# iOS

On iOS, your screens are drawn with UIKit: a `Button` is a `UIButton`, a `TextInput` a `UITextField`, a `ScrollView` a `UIScrollView`. The app that `leptoskit new` generates is a small UIKit app that runs your screens as WebAssembly, so it can also replace them over the air with [code push](../guide/05-code-push.md). Text is measured with the same fonts UIKit draws it with, so each label and button gets exactly the space it needs.

The generated app runs your screens' code on a thread of its own, not UIKit's main thread. Updating state, laying the screen out, and measuring text happen there, and the main thread only applies the result to the views. A slow update delays what you draw next, but scrolling, animations, and touches keep running meanwhile.

## What you need

- A Mac with Xcode and an installed iOS simulator runtime.
- The Rust targets for the simulator and for devices:

```bash
rustup target add aarch64-apple-ios-sim aarch64-apple-ios wasm32-unknown-unknown
```

On an Intel Mac, the simulator target is `x86_64-apple-ios`.

You don't need CocoaPods. A plugin's Swift Package Manager dependencies resolve automatically, and CocoaPods is needed only when a plugin declares `apple-pods` — leptoskit then writes the Podfile and runs `pod install` itself before every build. `leptoskit doctor` says when CocoaPods is required.

## Develop with live reload

```bash
leptoskit dev --platform ios
```

`dev` builds the app for the simulator, installs it in every booted iOS Simulator, and opens it. With no simulator booted, it boots the newest iPhone simulator. When you save, it rebuilds your interface and the running app swaps it in. [Building and serving](../guide/04-building.md#leptoskit-dev) covers the rest.

## Run it in the simulator

```bash
leptoskit native build ios-simulator
open .leptoskit/ios/Host.xcodeproj
```

The first command compiles your app to WebAssembly, compiles the UIKit host, and generates an Xcode project. In Xcode, pick a simulator and press **Run**. Simulator builds are signed ad hoc, so you don't need a development certificate.

The Xcode project is regenerated by every build. Make your changes in the `ios/` folder instead: `App.swift` starts the app, `Info.plist` holds its name, version, and permission strings, and `Cargo.toml` lists native Rust dependencies such as [runtime plugins](plugins.md).

## Run it on a device

```bash
leptoskit build --platform ios
```

This builds for `aarch64-apple-ios`. Device builds are not signed: open `.leptoskit/ios/Host.xcodeproj`, choose your development team under **Signing & Capabilities**, and run it on your device. `leptoskit build --release --platform ios` archives the app and exports an `.ipa` signed for your team, for the App Store, ad hoc, or development devices; see [Signing a release](../guide/24-signing.md#ios). For TestFlight and the App Store, `leptoskit publish app_store` archives, signs, and uploads the app; see [Publishing to the stores](../guide/24-publishing.md#the-app-store). The app's version is `app.version` from `leptoskit.toml`.

## Test it

Each project includes a UI test, `ios/AppUITests.swift`, that taps **Add one** and waits for **Count: 1**. Update it when you change the home screen, then run it on a simulator:

```bash
xcodebuild -project .leptoskit/ios/Host.xcodeproj -scheme App \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=- test
```

## How it differs from macOS

- Generated apps also draw `Switch`, `Checkbox`, `Radio`, `Slider`, `LinearProgressIndicator`, and `ActivityIndicator`, alongside `View`, `Text`, `Button`, `Pressable`, `TextInput`, `PasswordInput`, `TextArea`, `ScrollView`, `Image`, `Vector`, and `Rive`. Switches and sliders use UIKit controls; checkboxes and radio options use system-symbol buttons. Control callbacks propose state changes: update the component's controlled value in the callback to keep the new selection or value.
- In generated apps, tapping outside a text field ends editing without consuming the tapped button's action. Return ends editing and sends the field's submit event; a submit handler can move focus to another field with `.focused(...)`. Dragging a scroll view can dismiss the keyboard interactively.
- [3D scenes](../guide/33-3d-scenes.md) draw with Metal into a `CAMetalLayer`, on a display link that runs only while the scene changes or animates. `leptoskit build` bundles the app's `assets/` folder when the app uses `leptoskit`'s `3d` feature. Native scene views send primary-pointer input through `Scene::next_pointer`: positions are fractions of the view and movement uses layout units, so drag sensitivity stays the same across display densities.
- [Rive](../guide/20-rive.md) displays native vector frames in a `UIImageView`. The generated host uses a display link, pauses when backgrounded or clipped offscreen, and follows Reduce Motion. Text, image, layout, script, and audio assets are rejected by the native renderer.
- Transforms and [animations](../guide/32-animations.md) run on Core Animation, springs included. A widget animating out is drawn above its former siblings until it is gone, and text color changes don't animate.
- A [`Modal`](../guide/07-shared-components.md#show-a-dialog-or-a-menu-above-the-screen) is a form sheet and a `Popover` is a system popover, on an iPhone as well as an iPad. A swipe down on the sheet, a press outside the popover, Escape on a hardware keyboard and the VoiceOver escape gesture ask to close. A popover is centred on its anchor with an arrow, so `placement` picks above or below and nothing more. With the backend crate, a controller you mount the tree in yourself calls `UIKitBackend::present_overlays` from `viewDidAppear:` to show an overlay that was open before the view joined a window; `UIKitHost` does this for you.
- iOS has no native checkbox or radio button, so `Checkbox` and `Radio` are drawn with `UIButton`.
- VoiceOver gets fewer roles than macOS's accessibility API, and no expanded or collapsed state.
- [Sign-in](../guide/23-sign-in.md#native-apps) uses the system's passkey sheet, and Sign in with Apple's own sheet for Apple, once your site vouches for the app and the app has the associated domain `webcredentials:` your site, which you add in Xcode; the generated project doesn't yet. Other providers open in an `ASWebAuthenticationSession`, never a web view in the app. Passkeys aren't offered in a text field's suggestions.
- A hardware keyboard or VoiceOver activates a button without showing its [pressed style](../guide/07-shared-components.md#style-the-pressed-state). A touch shows it.
- `Image` loads [`asset://` pictures](../guide/36-assets.md) from the app bundle and `file://` URLs; the backend crate also accepts `resource://` names from the app bundle. Neither loads web URLs.
- The generated app keeps your screen inside the safe area, below the status bar and above the home indicator. The strips around it take your root view's background, as a browser paints the page's background across the whole window, and the status bar switches to light text on a dark one. A root without an opaque background leaves the system background. With the backend crate, `UIKitHost` reports the insets instead, and `pt-safe` and the other [safe-area utilities](../guide/07-shared-components.md#clear-the-status-bar-and-home-indicator) pad by them.
- The [`picture-in-picture`](plugins.md) plugin reports whether system PiP is supported. Entering PiP still needs an attached video player, which this release does not provide, and iOS has no draw-over-apps overlay equivalent to Android's `SYSTEM_ALERT_WINDOW`.

## Live Activities and the Dynamic Island

To show a short-lived status on the Lock Screen or in the Dynamic Island while the user is outside the app, enable `leptoskit`'s `live-activities` (or `mobile-surfaces`) feature in your app crate, add `leptoskit_plugin_live_activities` to your iOS host package, and list `"live-activities"` under `native.plugins` in `leptoskit.toml`.

From Rust (`leptoskit::platform::live_activities`), your guest can:

- start, update, and end ActivityKit Live Activities (`start`, `update`, `end`, `list`);
- attach a Dynamic Island layout (`DynamicIslandLayout`: compact leading/trailing, minimal badge, expanded leading/trailing/center/bottom, and `#RRGGBB` keyline tint) with `ContentState::with_dynamic_island`;
- schedule stale dates and relevance scores with `ActivitySchedule`, `start_scheduled`, and `update_scheduled`;
- wait for a per-activity APNs update token (`wait_push_token`) or an iOS 17.2+ push-to-start token (`wait_push_to_start_token`).

```rust
use leptoskit::platform::live_activities::ContentState;
use leptoskit::platform::live_activities::Identifier;
use leptoskit::platform::live_activities::ScheduledStartRequest;
use leptoskit::platform::live_activities::StartRequest;
use leptoskit::platform::live_activities::guest::LiveActivities;
use leptoskit::platform::live_activities::island::ActivitySchedule;
use leptoskit::platform::live_activities::island::DynamicIslandLayout;

let island = DynamicIslandLayout::new()
	.compact("ETA", "4m")
	.minimal("4m")
	.expanded("Delivery", "4 min", "Driver nearby", "123 Market St");

let state = ContentState::new([("status", "Driver nearby")])?
	.with_dynamic_island(&island)?;

let request = StartRequest::new(
	Identifier::new("order-42")?,
	Identifier::new("delivery")?,
	"Order #42",
	state,
	true,
)?;
let schedule = ActivitySchedule {
	stale_after_seconds: Some(900),
	relevance_score: 0.9,
	allow_push_to_start: true,
};
let activities = LiveActivities::new()?;
activities
	.start_scheduled(&ScheduledStartRequest::new(request, schedule)?)
	.await?;
```

The plugin drives ActivityKit; your iOS app still owns the Widget Extension UI and entitlements:

- set `NSSupportsLiveActivities` to `true` in `ios/Info.plist` (and `NSSupportsLiveActivitiesFrequentUpdates` if you need frequent pushes);
- enable **Push Notifications** when requesting `wait_push_token` or `wait_push_to_start_token`;
- add a Widget Extension target in Xcode that imports `LeptosKitLiveActivities` and renders `LeptosKitLiveActivityAttributes`:

```swift
import ActivityKit
import LeptosKitLiveActivities
import SwiftUI
import WidgetKit

@available(iOS 16.1, *)
struct DeliveryLiveActivityWidget: Widget {
    var body: some WidgetConfiguration {
        ActivityConfiguration(for: LeptosKitLiveActivityAttributes.self) { context in
            VStack(alignment: .leading) {
                Text(context.attributes.title).font(.headline)
                Text(context.state.fields["status"] ?? "")
            }
            .padding()
        } dynamicIsland: { context in
            DynamicIsland {
                DynamicIslandExpandedRegion(.leading) { Text(context.state.expandedLeading ?? "") }
                DynamicIslandExpandedRegion(.trailing) { Text(context.state.expandedTrailing ?? "") }
                DynamicIslandExpandedRegion(.center) { Text(context.state.expandedCenter ?? context.attributes.title) }
                DynamicIslandExpandedRegion(.bottom) { Text(context.state.expandedBottom ?? "") }
            } compactLeading: {
                Text(context.state.compactLeading ?? "")
            } compactTrailing: {
                Text(context.state.compactTrailing ?? "")
            } minimal: {
                Text(context.state.minimal ?? "")
            }
        }
    }
}
```

A successful start means ActivityKit accepted the request, not that chrome appeared: Focus modes and a missing Widget Extension can still hide it. On Android, the same plugin wires Android 16+ Live Updates via `post_android_live_update`; macOS, Windows, Linux, and browsers return `Unavailable`. See the [plugin inventory](plugin-inventory.md) for the exact operations.

## Ship an update without the App Store

The App Store build carries the UIKit host, the interpreter, and a copy of your screens. To change the screens afterwards, publish a code push release for iOS:

```bash
leptoskit native bundle --target ios --out dist/ios
leptoskit codepush release --from dist/ios --platform ios --channel production
```

The app downloads the release when the user asks for an update, tries it, and keeps it only if it renders. Anything that needs new native code, such as a new plugin or permission, still needs an App Store release. [Code push](../guide/05-code-push.md) covers signing, publishing, and rollback, and [host projects](host-projects.md#code-push-in-the-generated-apps) the update flow inside the app.

A `focused(true)` request takes effect when the property changes. After the user dismisses the keyboard, unrelated renders do not focus the field again. Set focus to false and then true to request focus again. A [`FocusRequest`](../guide/15-accessibility.md#move-focus-once) says the same thing directly: each `request()` raises the keyboard on its text field once, and on any other widget it moves the VoiceOver cursor there.

## Home-screen, Lock Screen, StandBy, and Control Center widgets

Enable `leptoskit`'s `home-widgets` (or `mobile-surfaces`) feature, add `leptoskit_plugin_home_widgets` to your iOS host package, and list `"home-widgets"` in `native.plugins`.

The [`home-widgets`](plugin-inventory.md) plugin stores bounded widget payloads in an App Group `UserDefaults` suite and triggers WidgetKit reloads:

- **Home, Lock Screen, and StandBy widgets:** `set` / `get` / `clear` single snapshots, `set_timeline` / `get_timeline` for multi-entry `TimelineSchedule`s (`SurfaceKind::HomeSmall` through `HomeExtraLarge`, `LockScreenCircular`, `LockScreenRectangular`, `LockScreenInline`, and `StandBy`), and `reload` (`WidgetCenter.shared.reloadTimelines` / `reloadAllTimelines`).
- **iOS 18+ Control Center controls:** `set_control` / `get_control` (`ControlCenterControl` with `ControlKind::Toggle` or `ControlKind::Button`, SF Symbol names, and `WidgetAction` deep links) and `reload_controls` (`ControlCenter.shared.reloadControls` / `reloadAllControls`).

Share an App Group between your app and Widget Extension and add its identifier under the `LeptosKitAppGroup` key in both targets' `Info.plist` files; `HomeWidgetsPlugin` reads `LeptosKitAppGroup` automatically so the extension and app read the same suite. In your SwiftUI Widget Extension or ControlWidget target, decode the published data with `LeptosKitWidgetStore`:

```swift
import LeptosKitHomeWidgets
import WidgetKit

// Inside your TimelineProvider:
let snapshot = LeptosKitWidgetStore.readSnapshot(kind: "summary")

// Inside an iOS 18+ ControlValueProvider:
let control = LeptosKitWidgetStore.readControl(id: "focus-mode")
```

Your app still owns the Widget Extension target and its SwiftUI views. Without an App Group, `capability` reports that the shared store is not ready and snapshots stay in standard defaults. WidgetKit cannot say whether a kind is pinned, so `installed` always answers `Unknown`.

## Quick Actions, CoreSpotlight, Handoff, Share Extensions, and iPadOS chrome

Enable `leptoskit`'s `app-shortcuts` (or `mobile-surfaces`) feature, add `leptoskit_plugin_app_shortcuts` to your iOS host package, and list `"app-shortcuts"` in `native.plugins`.

The [`app-shortcuts`](plugin-inventory.md) plugin wires:

- **Home-screen Quick Actions:** `set`, `clear`, and `consume_launch` for up to eight `UIApplicationShortcutItem` items.
- **CoreSpotlight search indexing:** `index_spotlight` and `delete_spotlight` (`SpotlightItem` with domain, keywords, deep link, and expiration) backed by `CSSearchableIndex.default()`.
- **Handoff and Continuity:** `start_user_activity` and `end_user_activity` (`UserActivity` with activity type, HTTPS webpage fallback, Handoff/Spotlight/Siri eligibility) backed by `NSUserActivity`.
- **Incoming Share Extensions:** `consume_incoming_share` returns the next `IncomingShare` recorded by your Share Extension or app delegate through `AppShortcutsPlugin.shared?.noteIncomingShare(text:url:subject:)`.
- **Typed Apple descriptors:** `AppIntentDefinition` (Siri / Shortcuts voice phrases), `StatusBarConfig`, `SheetDetent` (`Medium`, `Large`, `Fraction`), `MultiSceneConfig`, and `PencilPreference` live in `leptoskit::platform::app_shortcuts::integrations`.

## Menu bar and hardware keyboard commands

On iPadOS (and iOS with a hardware keyboard or Mac Catalyst), UIKit exposes a system menu bar (`UIMenuBuilder`) and the Cmd-hold keyboard shortcut HUD (`UIKeyCommand`). Enable `leptoskit`'s `menu` (or `mobile-surfaces`) feature and describe menu sections and shortcuts with `leptoskit::platform::menu::ios`:

```rust
use leptoskit::platform::menu::Command;
use leptoskit::platform::menu::ios::IosMenuBar;
use leptoskit::platform::menu::ios::IosMenuPlacement;
use leptoskit::platform::menu::ios::IosMenuSection;
use leptoskit::platform::menu::ios::KeyCommand;
use leptoskit::platform::menu::ios::KeyModifier;

let file_section = IosMenuSection::new(
	"file.notes",
	"Notes",
	IosMenuPlacement::File,
	vec![
		Command("new_note")
			.label("New Note")
			.accelerator("Cmd+N")
			.into(),
	],
)
.unwrap();

let quick_open = KeyCommand::new("quick_open", "Quick Open", "k", [KeyModifier::Command])
	.unwrap()
	.discoverability_title("Jump to any note")
	.unwrap();

let menu_bar = IosMenuBar::new()
	.section(file_section)
	.unwrap()
	.key_command(quick_open)
	.unwrap();
assert_eq!(menu_bar.sections().len(), 1);
```

Placements map directly to UIKit's standard `UIMenu.Identifier` slots (`Application`, `File`, `Edit`, `Format`, `View`, `Window`, `Help`, or `Custom`). Duplicate shortcut chords are rejected before native installation.

iOS APNs registration, second patch: the answers are now honest about silence and tight about what crosses. `REMOTE_REGISTER` bounds OS requests at one — later callers join the wait instead of asking again — and answers `Unconfirmed` (state 3) when its wait bound passes with no new answer, so a prior token is never handed back as though it were fresh; the broker keeps the last answer readable through `REMOTE_TOKEN`, and a plugin closed while waiting never answers a token. Registration refusals cross as the contract's stable codes — `os-refused`, `aps-environment` (matched on domain and code), `token-shape` — never the OS's own error text, which can carry device detail and previously clipped to invalid UTF-8. The token is an even count of hex characters (whole bytes, whatever length the OS chose), the revision is a consistent full `u64` with `0` meaning no answer on both constructor and decoder, the Swift broker's counter saturates instead of trapping, and no `Debug` or description of token, state, or snapshot prints its bytes. The browser implementation moved behind a default `browser` feature (as the HTTP plugin's did), so interpreter guests turn it off and their dependency tree stays free of browser imports.

iOS push enrollment, second patch: the `native` module now covers the whole launch lifecycle, not just the gesture. `reconcile(previous)` is the launch half and runs only for a device that previously opted in — the saved enrollment is the record — registering with APNs again without prompting (Apple expects it each launch) and never silently re-enabling a device that opted out. Its answer is an explicit transition: `Kept` (same token, same endpoint id, one idempotent call), or `Rotated { current, retired }` where the previous handle is verified against the signed-in person's endpoint list and retired under its owner with the stable `disable` key — rotated tokens never leak orphan endpoints, the quota refusal at ten endpoints is answered by retiring the known-stale handle and re-registering once, and a previous account's leftover handle is reported as `Stale` and dropped without ever being operated under the new identity. Errors name their retry state: `Unconfirmed` leaves the previous enrollment untouched, `Enroll` carries the handle to keep (or none once retired), and `RetireFailed`/`OwnershipUnknown` leave the new enrollment live with the old handle named for retry. The plugin contract is now an optional dependency behind `native` (guest side alone), so the shared types and the service build without it and without its Linux backend; silence answers `Unconfirmed` instead of replaying a stale token, and tokens never print through `Debug`. The whole guest control flow — plugin guest transport and RPC client over the HTTP plugin guest included — runs in a compiled wasm guest against played OS and service boundaries (`crates/leptoskit_wasm/tests/notifications_guest.rs`, wired into `test:plugins:guest`).

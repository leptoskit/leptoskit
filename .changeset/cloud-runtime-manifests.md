LeptosKit Cloud's runtime crate: a release as data, and the Kubernetes objects that carry it. `ReleaseSpec` is the whole desired state of one environment — the app and its services with exact image digests, ports, health paths, environment and secret variables, resources, scale, and volumes; the routes; and the policy — with typed validation that refuses a spec no runtime could honor, and a namespace hashed from the organisation, project, and environment ids so no customer-chosen name ever reaches Kubernetes. The `Runtime` trait is the adapter boundary (`apply`, `status`, `logs`, `destroy`), usable as `dyn Runtime`, with a recording fake behind the `testing` feature that validates specs and scripts ready, never-ready, and unavailable rollouts. The `kubernetes` feature builds the release's manifests deterministically: the namespace under the restricted Pod Security profile, quota and limit range, default-deny network policies with the release's doors only, a token-less service account, hardened Deployments, Services, KEDA's HTTP scaled object or a horizontal autoscaler, disruption budgets, and Ingresses with wildcard or cert-manager certificates — refusing, before anything is applied, sleep without the HTTP add-on, cookie stripping a plain Ingress cannot do, a secret with no value, and an issued certificate with no issuer.
